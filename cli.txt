COMANDOS Y OPCIONES DEL EJECUTABLE `stxt`
=========================================

--- IMPLEMENTADOS (v0.1.0) ---

stxt --version, -v
    Muestra la versión del CLI y del parser que usa (@stxt-lang/core).

stxt --help, -h
    Muestra la ayuda con los comandos disponibles.


--- ENTORNO Y RESOLUCION (v0.2.0) ---

stxt install <file> [--local|--user|--system|--root <dir>]
    Instala un schema o template **local** en el sistema de resolución.
    --local:    en ./\.stxt/ del proyecto actual (por defecto)
    --user:     en ~/.stxt (directorio del usuario)
    --system:   en /etc/stxt (o %ProgramData%\stxt en Windows). Es posible tener que usar con `sudo`
    --root <dir>: en el directorio especificado
    
    NOTA: Las URLs remotas (stxt install <url>) se descartaron por razones de seguridad.
            Descarga el archivo manualmente y usa un path local. Ejemplo en local:
                curl -O https://schemas.stxt.dev/blog.stxt
                stxt install ./blog.stxt --local

stxt schemas [path]
    Lista todos los namespaces resolubles para un documento, según su cadena de resolución.
    Sin <path>: usa el directorio de trabajo actual.
    Con <path>: muestra los schemas que se aplicarían a un documento en esa ubicación.
    Útil para diagnosticar por qué un documento no valida o qué definiciones son activas.


--- VALIDACION (v0.3.0) ---

stxt check <file|dir>... [--recursive|-r] [--format text|json] [--warn-schema|--no-schema]
    Valida uno o más documentos STXT: parsea y verifica contra los schemas descubiertos en
    la cadena de resolución de cada documento (la misma de `install`/`schemas`).
    --recursive, -r: obligatorio para pasar un directorio; desciende en subdirectorios,
                    procesando *.stxt y saltándose los directorios .stxt/ (son la cadena
                    de resolución, no documentos).
    --format text:  una línea por hallazgo (por defecto): "fichero:línea: [CODIGO] mensaje (severidad)"
    --format json:  un array JSON con {file, line, code, message, severity}, para herramientas/CI
    --warn-schema:  los errores de schema se muestran pero NO hacen fallar el build (solo los
                    errores de sintaxis del lenguaje base lo hacen)
    --no-schema:    no resuelve ni valida contra ningún schema; solo revisa la gramática base
    (sin flags): por defecto, un error de schema falla el build igual que uno de sintaxis.
    SCHEMA_NOT_FOUND nunca se reporta si la cadena de resolución del documento no tiene
    ningún schema cargado (los schemas son una capa opcional): un documento sin forma de
    validarse no está mal, solo no se puede validar.


--- FORMATO (v0.4.0) ---

stxt format <file|dir>... [--tabs|--spaces-4] [--check|--dry-run] [--clean]
    Re-escribe los documentos STXT aplicando el formato canónico.
    --tabs:       usa tabuladores para la indentación (por defecto)
    --spaces-4:   usa 4 espacios para la indentación
    --check, --dry-run: no escribe cambios, sale con código 1 si algo modificaría
    --clean:      además de formatear, elimina los comentarios


--- CONVERSION (v0.5.0) ---

stxt parse <file>
    Parse el documento y emite su árbol JSON canónico por stdout.
    Útil para testing entre implementaciones (JS, Java, etc.).

stxt from-json <file>
    Convierte un archivo JSON al formato STXT equivalente.
    Inverso de 'parse'.

stxt compile <template>
    Convierte un documento @stxt.template en su schema equivalente @stxt.schema.
